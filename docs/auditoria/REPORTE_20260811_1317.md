## 3. ESTADO OFFLINE FIRST
- **Funcionamiento local:** La app móvil puede registrar entregas, recepciones, puntos GPS y eventos de pedidos sin conectividad a internet usando la base de datos unificada SQLite (`LocalDb`).
- **Idempotencia y Manejo de Conflictos:**
  - Subida de evidencias fotográficas en `EntregasLocalService` y `RecepcionesLocalService` usa la convención determinista `<entidad_id>_<nombre_local>` con `upsert: true`, evitando duplicación de objetos en Supabase Storage tras reintentos por pérdida de señal.
  - Reintentos con manejo de excepciones `PostgrestException` para códigos PostgreSQL `23505` (duplicados ignorados/manejados) y `P0001` (marca de conflicto de negocio `sincronizado = 2`).
- **Corrección de Pendientes en UI:**
  - `_hasDataPending()` en `NetworkProvider` omitía la verificación de `eventos_pedidos_offline`, lo que provocaba que un usuario offline con un evento registrado no viera reflejado el indicador visual de datos pendientes hasta tener otro tipo de registro. Esto fue corregido en esta ejecución.

## 5. HALLAZGOS CRÍTICOS (🔴)

### 🔴 Hallazgo 1: Migración del RPC `ajustar_stock_atomico` no versionada en el directorio estándar
- **Path:** `sigo-wm/supabase/migrations/`
- **Función / Componente:** RPC PostgreSQL `ajustar_stock_atomico`
- **Problema:** El servicio Angular (`inventario.service.ts` L25, L63, L96) invocaba `this.supabase.rpc('ajustar_stock_atomico', ...)` para descontar y reponer stock de forma atómica. Sin embargo, la migración SQL no estaba dentro de `sigo-wm/supabase/migrations/`, sino aislada en un directorio accidental untracked (`Users/`).
- **Evidencia / Cita Literal:**
  - `sigo-wm/src/app/core/services/inventario.service.ts:L25`:
    ```typescript
    const { error } = await this.supabase.rpc('ajustar_stock_atomico', {
    ```
- **Impacto:** En un entorno nuevo de despliegue o CI/CD con `supabase db push`, la función RPC no se creaba, rompiendo los flujos de ventas e inventario web.
- **Afecta:** Web (Angular) / Supabase DB.
- **Estado:** 🔴 **CORREGIDO EN ESTA EJECUCIÓN**.

### 🔴 Hallazgo 2: Omisión de `eventos_pedidos_offline` en la verificación del badge de pendientes de `NetworkProvider`
- **Path:** `sigo_wm_mobile/lib/core/providers/network_provider.dart`
- **Línea:** 287
- **Función:** `_hasDataPending()`
- **Problema:** La consulta `rawQuery` con `EXISTS` revisaba `eventos_chofer_offline`, pero ignoraba la tabla `eventos_pedidos_offline` (donde `EventosLocalService.guardarEventoOffline` inserta los cambios de estado como 'EN CAMINO').
- **Evidencia / Cita Literal:**
  - `sigo_wm_mobile/lib/core/providers/network_provider.dart:L287`:
    ```dart
    EXISTS(SELECT 1 FROM eventos_chofer_offline WHERE sincronizado = 0) AS eventos
    ```
- **Impacto:** Si un chofer marcaba 'EN CAMINO' sin conexión, la propiedad `hasPendingData` devolvía `false` (si no existían otros registros), impidiendo mostrar el badge de alerta en la UI.
- **Afecta:** Mobile (Flutter) / UI Offline.
- **Estado:** 🔴 **CORREGIDO EN ESTA EJECUCIÓN**.
