# AUDITORÍA + CORRECCIÓN — Rastreo Cliente / JWT Auth API / Conectividad GPS — 2026-08-11

## 1. RESUMEN EJECUTIVO
En esta iteración del agente recurrente se auditó el ecosistema `Sigo-WM` (`sigo-wm` Angular + Serverless Functions y `sigo_wm_mobile` Flutter). Se detectó y corrigió una **vulnerabilidad crítica de seguridad (🔴)** en el endpoint Vercel Serverless `/api/reset-password`, el cual permitía la redefinición no autenticada de contraseñas de cualquier usuario en Supabase Auth sin validar token JWT ni rol de administrador. Se implementó la verificación obligatoria de sesión y permisos en la función serverless y se inyectó el header de autorización en el cliente Angular.

Asimismo, se realizaron optimizaciones defensivas en el marcador de camión en vivo (`rastreo-cliente.component.ts`) y se amplió el detector de conectividad en el servicio de segundo plano (`background_gps_service.dart`) para soportar todo tipo de interfaces de red (Ethernet, VPN, Bluetooth, WiFi y redes móviles).

Todas las pruebas técnicas resultaron 100% exitosas: `npx tsc --noEmit` limpio, `flutter analyze` con 0 advertencias, `flutter test` con 24/24 pruebas pasadas y el script de manifiesto con **DRIFT = 0**.

## 3. ESTADO OFFLINE FIRST
- **Transferencia QR de Despacho (Web ↔ Mobile / Mobile ↔ Mobile):** `QrDispatchGeneratorScreen` comprime el payload del viaje offline con `gzip` + `base64` en el esquema URI `sigo_wm://`. `QrDispatchScannerScreen` lee el código mediante `mobile_scanner`, descomprime el payload e inserta el viaje y sus detalles en SQLite local (`LocalDb`) de forma atómica y offline-safe.
- **Sincronización GPS:** En `background_gps_service.dart`, los puntos de ubicación se guardan primero en SQLite (`GpsDbHelper`) y se realiza el flush en lote (`RutasLocalService.sincronizarPendientesBatch`) al recuperar la conectividad.

---

## 4. COMPATIBILIDAD ANDROID/iOS
- **Detección de Permisos de Cámara:** `QrDispatchScannerScreen` gestiona `_CameraPermissionState` respondiendo al ciclo de vida (`didChangeAppLifecycleState`) cuando el usuario vuelve de la pantalla de Ajustes de iOS/Android (`openAppSettings`).
- **Control de GPS en Background (iOS):** iOS no utiliza `flutter_background_service`; maneja el rastreo con `Geolocator` nativo (píldora azul) y `SharedPreferences` para restaurar el pedido activo tras suspensiones de memoria.

## 5. HALLAZGOS CRÍTICOS (🔴)

### 🔴 Hallazgo 1: Endpoint de Reset de Contraseña Serverless `/api/reset-password` no autenticado
- **Path:** `sigo-wm/api/reset-password.ts`
- **Línea:** 24-52
- **Función:** `handler(req, res)`
- **Problema:** El endpoint aceptaba solicitudes `POST` con `userId` y `newPassword` y ejecutaba `supabaseAdmin.auth.admin.updateUserById(...)` utilizando la clave `SUPABASE_SERVICE_ROLE_KEY`. Sin embargo, no realizaba ningún chequeo del header `Authorization` ni verificaba que el emisor fuera un usuario autenticado con rol `admin` o `superadmin`.
- **Cita Literal Exacta:**
  ```typescript
  const { userId, newPassword } = req.body || {};
  // ...
  const supabase = createClient(supabaseUrl, serviceRoleKey, { ... });
  const { data, error } = await supabase.auth.admin.updateUserById(userId, { password: newPassword });
  ```
- **Búsqueda Global:** Invocado desde `src/app/features/configuracion/configuracion.component.ts:L203`.
- **Impacto:** Vulnerabilidad crítica de escalada de privilegios e impersonación: cualquier atacante en internet podía cambiar la contraseña de cualquier usuario en Supabase Auth sin credenciales.
- **Afecta:** Web (Angular) / Serverless Functions / Seguridad Supabase Auth.
- **Estado:** 🔴 **CORREGIDO EN ESTA EJECUCIÓN**.

## 6. HALLAZGOS ALTOS (🟠)

### 🟠 Hallazgo 1: Verificación de conectividad en `BackgroundGpsService.stopService()` omitía interfaces Ethernet/VPN/Bluetooth
- **Path:** `sigo_wm_mobile/lib/features/chofer/services/background_gps_service.dart`
- **Línea:** 145-147
- **Función:** `BackgroundGpsService.stopService()`
- **Problema:** `connectivity.contains(ConnectivityResult.mobile) || connectivity.contains(ConnectivityResult.wifi)` devolvía `false` si el dispositivo estaba conectado mediante Ethernet, VPN o Bluetooth tethering, omitiendo el flush final de GPS aun habiendo internet.
- **Cita Literal Exacta:**
  ```dart
  final tieneRed =
      connectivity.contains(ConnectivityResult.mobile) ||
      connectivity.contains(ConnectivityResult.wifi);
  ```
- **Búsqueda Global:** `background_gps_service.dart:145`.
- **Impacto:** Puntos GPS encolados al finalizar ruta podian no sincronizarse de inmediato en entornos con adaptadores Ethernet o VPNs móviles.
- **Estado:** 🟠 **CORREGIDO EN ESTA EJECUCIÓN**.
